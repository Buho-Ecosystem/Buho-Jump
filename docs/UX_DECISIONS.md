# Login and accessibility review decisions

Implemented against the September 2026 Apple Human Interface Guidelines. The source review is `UX_REVIEW.md`; this document records the rationale for the changes rather than treating a web extension as a native Apple control library.

| Decision | HIG comparison | Implementation |
|---|---|---|
| Use “Sign in,” an account name, and the requesting address | [Writing](https://developer.apple.com/design/human-interface-guidelines/writing): familiar vocabulary, action labels, important information first | Public-profile and authentication requests have a sign-in title. Website-controlled titles never replace or truncate the origin. |
| Keep three approval choices visible | [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons): one prominent default, consistent sizing, meaningful labels | A one-time action, explicit site trust, and “Not now” occupy a fixed footer. Each has at least 44px height. Only content scrolls. |
| Explain lasting trust before granting it | [Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy): explain access and give people control | The trust explanation names posts, private messages, and wallet access. Payment approval and user-selected budgets remain separate. Rules belong to an exact origin and account, and can be revoked in Sites. |
| Put protocol information behind Details | [Layout](https://developer.apple.com/design/human-interface-guidelines/layout): progressive disclosure and related groups | Event JSON, cryptographic terminology, server publishing, and account derivation paths are secondary. Payment amounts, authentication destinations, and post previews remain visible. |
| Show profiles in every account row | [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables): consistent, recognizable rows | One account identity component is reused in the switcher, settings, and removal sheets. Cached profiles render before background refresh. Missing profiles use an account icon and public-key identifier. |
| Do not imply a profile address proves identity | [Nostr Design: impostor prevention](https://nostrdesign.org/docs/how-to/impostor-prevention/) | A profile address is a display field, without a verified badge. Untrusted metadata is bounded and account avatars accept HTTPS only. |
| Expose Account navigation and simplify the header | [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): stable destinations with labels | Account joins Wallet and Chat. Wallet selection moves to Wallet. The unlocked settings menu contains Lock and Settings. |
| Raise caption sizes and contrast | [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility): readable type, contrast, keyboard access | 12px caption floor for this desktop web surface, larger body and title sizes, measured 4.5:1 minimum for muted/secondary/brand text on all base surfaces in every theme. Explicit focus rings and reduced-motion support. This is a project type scale, not a claim that Apple specifies a universal 12px floor. |
| Make secondary actions reachable without hovering | [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons): discoverability and sufficient target area | Real account-removal buttons, visible wallet/server actions, message action buttons, shared back buttons. Small desktop icon targets are at least 32px; touch targets expand to 44px. |
| Protect payment state when dismissing a flow | [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts): prevent accidental loss and explain consequences | Backdrop and Escape route through the flow. Newly created eCash stays visible until an explicit Done or reclaim action; active incoming requests ask before closing. Nested sheets trap focus independently. |
| Reduce duplicate implementations | [Consistency](https://developer.apple.com/design/human-interface-guidelines) | Shared account identity, deletion, back, unlock, and notification-settings components. |

The onboarding decision follows [HIG onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding): get people to useful work quickly and offer optional setup in context. New accounts go from name to done. Backup verification and profile publishing remain explicit next steps; an immediate reminder persists until backup verification succeeds. Password protection remains required. The shortened flow never marks a skipped backup as verified.

## Validation contract

Run `npm test`, `npm run locales:check`, `npm run build`, and `npm run test:ui`. The UI command renders the production bundle with synthetic accounts and payments; it does not access a real account, sign an event, or spend money. Install Playwright Chromium using `npx playwright install chromium`, or supply `BROWSER_PATH` for an installed Chromium browser. Screenshots default to `/private/tmp/buho-ux-review` and can be redirected with `UX_SCREENSHOTS`.

Prompt coverage includes every supported method, known action variants, unlock, all 17 locales, and the original 420×492 / 420×572 viewports as well as 420×652, plus unlock at 400×412. Assertions cover document overflow, visible action bounds, hit height, payment trust exclusion, approval failures, site blocking, account identity in the popup/settings/switch sheet, keeping fresh eCash visible on Escape, nested receive confirmations, and shortened account creation. Additional checks cover 150% root text sizing, both appearances, long origins, and stalled optional metadata.

No viewport test alone certifies complete HIG conformance. Check long names, both appearances, large text, keyboard use, and the flow's actual consequences when changing a screen.

## Translation provenance

The core prompt wording, all prompt translations, and the previously copied German passages were revised directly for this review. Remaining copied English passages in Czech, Danish, Finnish, Norwegian, and Swedish were drafted directly. Other locales received an automated Google Translate draft from public interface text only, followed by a terminology pass. Placeholder validation and source-copy checks are automated; a native-speaker editorial review remains appropriate before claiming each locale has been professionally reviewed. The extension has no runtime translation-service dependency.
